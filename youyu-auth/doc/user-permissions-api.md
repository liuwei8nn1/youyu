# 用户权限获取API文档

## 接口说明

该接口用于获取指定用户的所有权限码（permission codes），这些权限码基于用户的角色和角色关联的菜单权限。

## 接口地址

```
GET /api/auth/role-permission/getUserPermissions
```

## 请求参数

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| userId | Long | 是 | 用户ID |
| userType | Integer | 是 | 用户类型（1-顾客, 2-企业, 3-平台） |

## 响应示例

### 成功响应

```json
{
  "code": 200,
  "message": "success",
  "data": [
    "user:view",
    "user:create", 
    "user:update",
    "role:view",
    "menu:view"
  ]
}
```

### 空权限响应

```json
{
  "code": 200,
  "message": "success", 
  "data": []
}
```

## 业务逻辑

1. **获取用户角色**：通过Feign调用用户服务获取用户的角色编码列表
2. **查询角色信息**：根据角色编码和用户类型查询对应的角色ID
3. **获取菜单权限**：根据角色ID查询关联的菜单ID列表
4. **构建菜单树**：从缓存中获取全量菜单树，并根据用户权限过滤
5. **提取权限码**：从过滤后的菜单中提取所有非空的permissionCode字段
6. **去重返回**：对权限码进行去重后返回

## 权限码来源

权限码来源于菜单表（sys_menu）中的 `permission_code` 字段：
- DIRECTORY类型（目录）的菜单通常没有权限码（为NULL）
- MENU类型（菜单）和BUTTON类型（按钮）的菜单有具体的权限码
- 只有启用状态（status=1）且可见（visible=1）的菜单才会被包含

## 使用场景

1. **前端权限控制**：根据用户权限码动态显示/隐藏菜单项和操作按钮
2. **后端权限验证**：在API接口中进行细粒度的权限检查
3. **权限审计**：记录和分析用户的权限分布情况

## 注意事项

1. 如果用户没有分配任何角色，将返回空列表
2. 如果用户的角色没有关联任何菜单，将返回空列表  
3. 权限码会自动去重，确保每个权限码只出现一次
4. 该接口依赖用户服务的角色关联功能，需要确保user_role表中有正确的数据
