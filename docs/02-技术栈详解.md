## 消息队列

### RocketMQ Spring Boot Starter 2.3.0
- **版本**: 2.3.0
- **类型**: 消息队列
- **用途**:
  - 异步解耦
  - 流量削峰
  - 最终一致性保证
  - 秒杀订单处理
- **核心功能**:
  - 可靠消息发送
  - 消息补偿机制
  - 顺序消息
  - 事务消息

**可靠性设计**:
- mq.compensation 模块使用 JdbcTemplate 实现补偿记录存储
- 补偿记录保存失败必须抛出异常
- 支持可靠消息发送和失败重试

## 构建与依赖管理

### Maven
- **类型**: 项目构建工具
- **用途**:
  - 依赖管理
  - 项目构建
  - 多模块管理

### 多模块结构

#### 父工程
```xml
<groupId>com.youyu</groupId>
<artifactId>youyu</artifactId>
<version>0.0.1-SNAPSHOT</version>
```

#### 基础模块
- youyu-common: 公共模块（常量、工具类、基础实体）
- youyu-framework: 框架模块（核心功能实现、工厂类）
- youyu-starter: Starter 自动配置模块

#### 业务模块（每个包含 api/impl/sdk/bootstrap）
- youyu-auth: 认证授权服务
- youyu-user: 用户服务
- youyu-product: 商品服务
- youyu-order: 订单服务
- youyu-seckill: 秒杀服务
- youyu-gateway: 网关服务
- youyu-basics: 基础公共服务

### 依赖管理原则

#### 轻量化原则
**核心思想**: 尽量减少对外部框架的强制依赖

**实践案例**:
```
mq.compensation 模块：
- ❌ 不使用 MyBatis-Plus（重量级）
- ✅ 使用 JdbcTemplate（轻量级）
- 集成方只需提供 DataSource
- 表名可通过配置自定义
```

#### 版本统一管理
- 通过 `dependencyManagement` 统一管理所有依赖版本
- 子模块无需指定版本号
- 确保依赖版本一致性

#### 模块依赖关系
```
bootstrap → impl → api
         → sdk
    
impl → framework → common
sdk → api
```

## 技术选型理由

### 为什么选择 DDD 架构？
- 业务复杂度高（电商秒杀场景）
- 需要清晰的领域边界
- 便于长期维护和扩展
- 符合微服务设计理念

### 为什么选择 Redisson？
- 功能丰富（分布式锁、数据结构等）
- 性能优秀
- 社区活跃
- 与 Spring Boot 集成良好

### 为什么选择 RocketMQ？
- 高吞吐量
- 低延迟
- 可靠性强
- 阿里生态集成好
- 支持事务消息和顺序消息

### 为什么选择 Sentinel？
- 阿里巴巴开源
- 功能全面（限流、熔断、降级）
- 可视化控制台
- 与 Spring Cloud Alibaba 无缝集成

### 为什么 Framework 的 compensation 用 JDBC？
- 降低集成方依赖负担
- 轻量化设计
- 只需 DataSource 即可使用
- 避免引入完整的 ORM 框架
