## 架构设计最佳实践

### DDD 领域驱动设计

#### 聚合根设计原则

**1. 保持聚合小巧**
```java
// ✅ 正确 - 聚合只包含必要的实体
public class OrderAggregate {
    private OrderId id;
    private List<OrderItem> items;  // 订单项作为实体
    private Money totalAmount;      // 值对象
    
    // 业务方法在聚合根上
    public void addItem(Product product, int quantity) {
        // 保证聚合内的一致性
    }
}

// ❌ 错误 - 聚合过大，包含过多实体
public class OrderAggregate {
    private OrderId id;
    private User user;           // 不应该包含用户聚合
    private Product product;     // 不应该包含商品聚合
    private Address address;     // 应该用值对象
    // ... 太多关联
}
```

**2. 通过 ID 引用其他聚合**
```java
// ✅ 正确 - 只存储 ID
public class OrderAggregate {
    private UserId userId;       // 用户 ID
    private ProductId productId; // 商品 ID
}

// ❌ 错误 - 直接引用其他聚合对象
public class OrderAggregate {
    private UserAggregate user;      // 不要这样做
    private ProductAggregate product; // 不要这样做
}
```

**3. 聚合内保证一致性**
```java
public class OrderAggregate {
    private Money balance;
    
    public void pay(Money amount) {
        // 在聚合内部保证业务规则
        if (balance.compareTo(amount) < 0) {
            throw new DomainException("余额不足");
        }
        balance = balance.subtract(amount);
    }
}
```

#### 值对象设计

**特点**: 不可变、无独立身份、通过属性判断相等性

```java
@Value  // Lombok - 不可变
public class Money {
    BigDecimal amount;
    String currency;
    
    public Money add(Money other) {
        // 返回新对象，不修改自身
        return new Money(this.amount.add(other.amount), this.currency);
    }
    
    @Override
    public boolean equals(Object o) {
        // 基于属性值判断相等
        if (this == o) return true;
        if (o == null || getClass() != o.getClass()) return false;
        Money money = (Money) o;
        return amount.compareTo(money.amount) == 0 && 
               currency.equals(money.currency);
    }
}
```

#### 领域服务 vs 应用服务

**领域服务**: 封装跨多个聚合的业务逻辑

```java
// 领域服务 - 在领域层
@Component
public class OrderDomainService {
    
    /**
     * 创建订单（涉及订单和库存两个聚合）
     */
    public OrderAggregate createOrder(UserId userId, List<ProductId> productIds) {
        // 协调多个聚合
        // 检查库存
        // 创建订单
        // 扣减库存
    }
}
```

**应用服务**: 协调领域对象完成用例

```java
// 应用服务 - 在应用层
@Service
@Transactional
public class OrderApplicationService {
    
    @Autowired
    private OrderRepository orderRepository;
    
    @Autowired
    private OrderDomainService orderDomainService;
    
    public OrderVO createOrder(CreateOrderRequest request) {
        // 1. 参数转换
        UserId userId = new UserId(request.getUserId());
        List<ProductId> productIds = convert(request.getProductIds());
        
        // 2. 调用领域服务
        OrderAggregate order = orderDomainService.createOrder(userId, productIds);
        
        // 3. 持久化
        orderRepository.save(order);
        
        // 4. 返回结果
        return assembler.toVO(order);
    }
}
```

### 模块化设计

#### 公共服务合并策略

**适用场景**: 演示项目、原型项目、快速验证类项目

**策略**:
1. 短信服务与邮件服务合并为通知服务（通过类型区分）
2. 所有公共服务合并为基础服务（youyu-basics）
3. 基础服务内部按功能模块分包（file、notification 等）

**示例结构**:
```
youyu-basics/
├── file/          # 文件服务
├── notification/  # 通知服务（短信+邮件）
│   ├── sms/
│   └── email/
└── message/       # 消息服务
```

#### 依赖轻量化原则

**核心思想**: 尽量减少对外部框架的强制依赖

**实践案例**: mq.compensation 模块

```java
// ✅ 正确 - 使用 JdbcTemplate（轻量级）
@Configuration
public class CompensationAutoConfiguration {
    
    @Bean
    public CompensationService compensationService(DataSource dataSource) {
        JdbcTemplate jdbcTemplate = new JdbcTemplate(dataSource);
        return new CompensationServiceImpl(jdbcTemplate);
    }

// ❌ 错误 - 引入 MyBatis-Plus（重量级）
// 集成方必须引入 MyBatis-Plus 才能使用补偿功能
```

**优势**:
- 集成方只需提供 DataSource
- 降低依赖负担
- 表名可通过配置自定义

## 性能优化最佳实践

### 缓存优化

#### 多级缓存策略

```java
@Service
public class ProductService {
    
    @Autowired
    private CaffeineCache localCache;  // L1 - 本地缓存
    
    @Autowired
    private RedissonClient redisson;   // L2 - 分布式缓存
    
    public ProductVO getProduct(Long id) {
        // 1. 先查本地缓存
        ProductVO product = localCache.get(id);
        if (product != null) {
            return product;
        }
        
        // 2. 再查 Redis
        String key = "product:" + id;
        RBucket<ProductVO> bucket = redisson.getBucket(key);
        product = bucket.get();
        if (product != null) {
            // 回写本地缓存
            localCache.put(id, product);
            return product;
        }
        
        // 3. 最后查数据库
        product = loadFromDatabase(id);
        
        // 4. 写入缓存
        bucket.set(product, 10, TimeUnit.MINUTES);
        localCache.put(id, product);
        
        return product;
    }
}
```

#### 缓存穿透防护

```java
public ProductVO getProduct(Long id) {
    String key = "product:" + id;
    
    // 使用分布式锁防止缓存穿透
    RLock lock = redisson.getLock("lock:" + key);
    try {
        lock.lock(5, TimeUnit.SECONDS);
        
        // 双重检查
        ProductVO product = cache.get(key);
        if (product != null) {
            return product;
        }
        
        // 查询数据库
        product = loadFromDatabase(id);
        
        // 即使为空也缓存，防止穿透
        if (product == null) {
            cache.set(key, NULL_OBJECT, 1, TimeUnit.MINUTES);
        } else {
            cache.set(key, product, 10, TimeUnit.MINUTES);
        }
        
        return product;
    } finally {
        lock.unlock();
    }
}
```

### 在线状态管理优化

#### 按用户维度存储

**方案**: Redis Key 不区分设备，按用户维度存储

```java
// ✅ 正确 - 用户维度
String key = "user:online:" + userId;
redis.setex(key, timeout, timestamp);

// ❌ 错误 - 设备维度（占用更多空间）
String key = "user:online:" + userId + ":" + deviceId;
```

#### 通过 Token 刷新更新在线状态

**高并发优化**: 避免每次请求都写入 Redis

```java
@Component
public class OnlineStatusService {
    
    @Autowired
    private RedissonClient redisson;
    
    /**
     * 在 Token 刷新时更新在线状态
     * 而不是每次请求都更新
     */
    public void updateOnlineStatus(Long userId) {
        String key = "user:online:" + userId;
        long now = System.currentTimeMillis();
        
        // 只有距离上次更新超过一定时间才更新
        Long lastUpdate = redisson.getBucket(key).get();
        if (lastUpdate == null || now - lastUpdate > 60000) { // 1分钟
            redisson.getBucket(key).set(now, 5, TimeUnit.MINUTES);
        }
    }
}
```

**优势**:
- 减少 Redis 写入压力
- 降低网络开销
- 提升系统吞吐量

## 可靠性保障最佳实践

### MQ 可靠发送

#### 可靠消息发送流程

```java
@Service
public class OrderMessageService {
    
    @Autowired
    private RocketMQTemplate rocketMQTemplate;
    
    @Autowired
    private CompensationService compensationService;
    
    /**
     * 发送可靠消息
     */
    public void sendOrderCreatedMessage(OrderCreatedEvent event) {
        String messageId = UUID.randomUUID().toString();
        
        try {
            // 1. 保存补偿记录
            compensationService.saveRecord(messageId, event);
            
            // 2. 发送消息
            SendResult result = rocketMQTemplate.syncSend(
                "order-created-topic", 
                MessageBuilder.withPayload(event)
                    .setHeader(MessageConst.PROPERTY_KEYS, messageId)
                    .build()
            );
            
            // 3. 检查发送结果
            if (result.getSendStatus() != SendStatus.SEND_OK) {
                throw new InfrastructureException("消息发送失败");
            }
            
            // 4. 标记为已发送
            compensationService.markAsSent(messageId);
            
        } catch (Exception e) {
            log.error("发送消息失败，messageId: {}", messageId, e);
            // 补偿机制会重试
            throw e;
        }
    }
}
```

#### 补偿记录保存失败必须抛出异常

```java
// ✅ 正确 - 保存失败抛出异常
public void saveRecord(String messageId, Object payload) {
    int rows = jdbcTemplate.update(SQL, messageId, toJson(payload));
    if (rows == 0) {
        throw new InfrastructureException("保存补偿记录失败");
    }
}

// ❌ 错误 - 吞掉异常
public void saveRecord(String messageId, Object payload) {
    try {
        jdbcTemplate.update(SQL, messageId, toJson(payload));
    } catch (Exception e) {
        log.error("保存补偿记录失败", e);
        // 静默失败，导致补偿机制失效
    }
}
```

### 分布式锁

#### Redisson 分布式锁

```java
@Service
public class SeckillService {
    
    @Autowired
    private RedissonClient redisson;
    
    public boolean seckill(Long productId, Long userId) {
        String lockKey = "seckill:" + productId;
        RLock lock = redisson.getLock(lockKey);
        
        try {
            // 尝试获取锁，最多等待 3 秒，锁定 10 秒后自动释放
            boolean locked = lock.tryLock(3, 10, TimeUnit.SECONDS);
            if (!locked) {
                throw new BusinessException("系统繁忙，请稍后重试");
            }
            
            // 执行秒杀逻辑
            return doSeckill(productId, userId);
            
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
            throw new BusinessException("系统繁忙");
        } finally {
            // 确保释放锁
            if (lock.isHeldByCurrentThread()) {
                lock.unlock();
            }
        }
    }
}
```

### 熔断降级

#### Sentinel 注解化使用

```java
@Service
public class ProductService {
    
    /**
     * 使用 Sentinel 保护热点接口
     */
    @SentinelResource(
        value = "getProductDetail",
        blockHandler = "handleBlock",
        fallback = "handleFallback"
    )
    public ProductVO getProductDetail(Long productId) {
        // 正常业务逻辑
        return productRepository.findById(productId);
    }
    
    /**
     * 流控处理
     */
    public ProductVO handleBlock(Long productId, BlockException e) {
        log.warn("触发流控: productId={}", productId);
        return ProductVO.defaultProduct();
    }
    
    /**
     * 异常降级
     */
    public ProductVO handleFallback(Long productId, Throwable t) {
        log.error("服务降级: productId={}", productId, t);
        return ProductVO.defaultProduct();
    }
}
```

## 常见问题与解决方案

### 问题 1: Spring Boot Starter 自动配置路径错误

**现象**: 
```
ClassNotFoundException: com.youyu.starter.autoconfigure.web.IpRateLimitAutoConfiguration
```

**原因**: AutoConfiguration.imports 文件中的类路径与实际包结构不一致

**解决**:
```properties
# org.springframework.boot.autoconfigure.AutoConfiguration.imports

# ❌ 错误 - 路径不对
com.youyu.starter.autoconfigure.web.IpRateLimitAutoConfiguration

# ✅ 正确 - 与实际包结构一致
com.youyu.starter.autoconfigure.security.IpRateLimitAutoConfiguration
```

### 问题 2: @Value 缺少默认值导致启动失败

**现象**:
```
Could not resolve placeholder 'config.property' in value "${config.property}"
```

**解决**:
```java
// ❌ 错误
@Value("${config.property}")
private String property;

// ✅ 正确
@Value("${config.property:default_value}")
private String property;
```

### 问题 3: RocketMQTemplate 构造器注入失败

**现象**:
```
Parameter 0 of constructor required a bean of type 'RocketMQTemplate' that could not be found.
```

**原因**: 构造器注入时 Bean 尚未创建完成

**解决**:

**方式 1**: 字段注入
```java
@Component
public class MessageProducer {
    
    @Autowired
    private RocketMQTemplate rocketMQTemplate;
}
```

**方式 2**: @Lazy 延迟加载
```java
@Component
public class MessageProducer {
    
    private final RocketMQTemplate rocketMQTemplate;
    
    public MessageProducer(@Lazy RocketMQTemplate rocketMQTemplate) {
        this.rocketMQTemplate = rocketMQTemplate;
    }
}
```

**方式 3**: Setter 注入
```java
@Component
public class MessageProducer {
    
    private RocketMQTemplate rocketMQTemplate;
    
    @Autowired
    public void setRocketMQTemplate(RocketMQTemplate rocketMQTemplate) {
        this.rocketMQTemplate = rocketMQTemplate;
    }
}
```

### 问题 4: 循环依赖

**现象**:
```
The dependencies of some of the beans form a cycle
```

**解决**:

**方式 1**: 重构代码，消除循环依赖
```java
// 提取共同依赖到第三个服务
@Service
public class CommonService {
    // 原来 A 和 B 的共同逻辑
}

@Service
public class ServiceA {
    @Autowired
    private CommonService commonService;
}

@Service
public class ServiceB {
    @Autowired
    private CommonService commonService;
}
```

**方式 2**: 使用 @Lazy
```java
@Service
public class ServiceA {
    
    @Autowired
    @Lazy
    private ServiceB serviceB;
}
```

### 问题 5: MyBatis Plus 分页无效

**现象**: 分页查询返回全部数据

**原因**: 未配置分页插件

**解决**:
```java
@Configuration
public class MyBatisPlusConfig {
    
    @Bean
    public MybatisPlusInterceptor mybatisPlusInterceptor() {
        MybatisPlusInterceptor interceptor = new MybatisPlusInterceptor();
        interceptor.addInnerInterceptor(new PaginationInnerInterceptor(DbType.MYSQL));
        return interceptor;
    }
}
```

### 问题 6: Feign 调用超时

**现象**:
```
Read timed out executing GET http://user-service/api/users/1
```

**解决**:
```yaml
feign:
  client:
    config:
      default:
        connectTimeout: 5000
        readTimeout: 10000
```

## 关键决策记录

### 1. 国际化常量位置
**决策**: BaseI18nKey 放在 youyu-common 模块  
**原因**: 避免循环依赖，符合模块化最佳实践

### 2. Refresh Token 策略
**决策**: 轻量级零存储，滚动刷新  
**原因**: 利用 JWT 自然过期机制，无需额外存储

### 3. 在线状态管理
**决策**: 按用户维度存储，不区分设备  
**原因**: 减少 Redis 空间占用，简化查询逻辑

### 4. 设备标识
**决策**: 排除 IP 地址，仅用浏览器特征  
**原因**: IP 动态变化，不适合作为设备标识

### 5. 依赖轻量化
**决策**: mq.compensation 使用 JDBC  
**原因**: 降低集成方依赖负担

### 6. 异常处理
**决策**: 补偿记录保存失败必须抛出异常  
**原因**: 确保数据一致性，避免静默失败

### 7. 验签优化
**决策**: 签名计算不包含 body  
**原因**: 减少前端压力，提高性能
