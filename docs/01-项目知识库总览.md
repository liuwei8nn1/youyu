## 项目概述

### 基本信息
- **项目名称**: Youyu 电商秒杀系统
- **架构模式**: DDD（领域驱动设计）+ 微服务
- **构建工具**: Maven 多模块项目

### 模块架构

本项目采用 **三层微服务架构**，逻辑上划分为基础支撑、公共能力和业务应用三个层次：

#### 1. 基础支撑层
为所有微服务提供技术底座和通用能力：
- **youyu-common**: 纯 Java 工具类（无框架依赖）
- **youyu-framework**: 核心框架封装（Web、Security、Cache、MQ、Datasource 等）
- **youyu-starter**: Spring Boot 自动配置（简化业务服务接入）

#### 2. 公共能力层
提供跨业务的公共服务：
- **youyu-basics**: 基础公共服务（文件上传、通知服务等）
  - 内部按功能域分包：`file/`, `notification/`

#### 3. 业务应用层
直接面向用户和业务场景，包含网关入口与核心业务微服务：
- **网关服务**:
  - **youyu-gateway**: API 网关（路由转发、鉴权、限流）
- **业务微服务** (每个服务均包含 api/impl/sdk/bootstrap 四个子模块):
  - **youyu-auth**: 认证授权服务
  - **youyu-user**: 用户服务
  - **youyu-product**: 商品服务
  - **youyu-order**: 订单服务
  - **youyu-seckill**: 秒杀服务

## 数据库管理

### SQL 文件组织结构
本项目采用**两级文档管理**策略，SQL 脚本随模块独立管理：

```
youyu-auth/sql/init-auth.sql             # 认证授权模块（7张表）
youyu-user/sql/init-user.sql             # 用户模块（2张表）
youyu-product/sql/init-product.sql       # 商品模块（4张表）
```

开发环境建议按以下顺序执行各模块的 SQL 脚本：
1. **Auth 模块**（基础认证）
2. **User 模块**（用户资料）
3. **Product 模块**（商品信息）
4. **Order 模块**（订单管理）
5. **Seckill 模块**（秒杀功能）

## 架构设计

### DDD 分层架构

#### 分层结构
```
interfaces → application → domain ← infrastructure
```

**依赖方向**: 符合依赖倒置原则，领域层不依赖任何框架和基础设施

#### 各层职责

1. **Interfaces 层（用户接口层）**
   - 处理 HTTP 请求
   - 参数校验
   - 响应格式化

2. **Application 层（应用层）**
   - 协调领域对象完成业务用例
   - 不包含核心业务规则

3. **Domain 层（领域层）** - 核心业务逻辑
   - 聚合根（Aggregate Root）
   - 实体（Entity）
   - 值对象（Value Object）
   - 领域服务（Domain Service）
   - 仓储接口（Repository Interface）

4. **Infrastructure 层（基础设施层）**
   - 实现 Repository 接口
   - 提供技术实现（数据库访问、缓存、消息队列等）

#### 设计原则
- 领域层不依赖任何框架和基础设施
- 通过 Repository 接口与基础设施层解耦
- 应用层协调领域对象但不包含业务规则
- 接口层只做参数校验和响应格式化

### 安全架构分层设计

**分层防护策略**:
- **外部网关**: 负责通用安全（轻量级验签，基于 Header+Path）
- **业务微服务**: 负责核心业务安全（如需，可对 Body 进行全量验签）

**优势**: 实现关注点分离，兼顾性能与灵活性

**注意**: 验签签名计算不包含 body，以减少前端压力

### 设备标识策略

**禁止使用 IP 地址作为设备标识**，原因：
1. 动态 IP：移动网络、DHCP 环境下 IP 频繁变化
2. 代理/VPN：用户使用代理或 VPN 会导致 IP 变化
3. 网络切换：WiFi 与 4G 切换时 IP 也会改变

**正确做法**: 仅使用浏览器/设备本身的固有特征参数组合生成设备 ID，如 User-Agent、Sec-Ch-Ua、Sec-Ch-Ua-Platform 等

### 设备 ID 双字段设计

- **deviceUniqueId**: 设备唯一标识（基于浏览器特征生成）
- **deviceId**: 设备记录 ID（数据库主键）

### Token 管理策略

#### Refresh Token 滚动刷新方案
- **轻量级零存储**: 不单独存储 Refresh Token
- 利用 JWT 自然过期机制
- 滚动刷新延长会话有效期

#### 在线状态管理
- **按用户维度存储**: Redis Key 不区分设备
- **高并发优化**: 通过 Token 刷新机制更新在线状态，避免频繁写入

### 用户类型联合查询设计

使用 `UserIdentity` 包含 `userId` 和 `userType`，支持联合查询和用户身份识别

## 开发规范

### DDD 命名规范

**数据库对象命名**:
- 基础设施层持久化实体: `XXXDO`（避免与领域层实体混淆）
- 领域层聚合根: `XXXAggregate`
- 领域实体: 直接使用领域名词命名

**示例**:
```java
// 基础设施层
public class UserDO { }

// 领域层
public class UserAggregate { }
public class Order { }
```

### Sentinel 使用规范

**注解化使用**:
- 使用 `@SentinelResource` 注解简化配置
- 统一异常处理策略
- 避免硬编码资源名

### Framework 与 Starter 模块职责划分

**Framework 模块**:
- 提供核心功能实现
- 工厂类归属（如 WarnChannelFactory）
- 可被多个 Starter 引用

**Starter 模块**:
- 自动配置（AutoConfiguration）
- Bean 创建和管理
- 条件装配（@ConditionalOnProperty）

**原则**: 工厂类放在 framework，自动配置放在 starter

### 国际化常量放置规范

**BaseI18nKey 等基础国际化常量应放在 youyu-common 模块中**

**原因**:
- 避免循环依赖
- framework 模块通过 Maven 依赖引用 common 模块
- 符合模块化最佳实践

### 补偿记录保存失败必须抛出异常

**原则**: 补偿表保存失败时必须抛出异常，让业务层感知

**原因**:
- 确保数据一致性
- 避免静默失败导致补偿机制失效
- 让上层业务能够正确处理异常情况

### 包结构组织规范

**Starter 模块包结构**:
- 按功能模块组织：web/data/security/logging/trace/warn/base/i18n 等
- AutoConfiguration.imports 文件中类路径必须与实际包结构完全一致

**AntiShake 和 Cache 重构**:
- 防抖功能独立为 AntiShake 模块
- 缓存功能独立为 Cache 模块
- 清晰的职责划分

## 最佳实践

### 依赖轻量化原则

**核心思想**: 尽量减少对外部框架的强制依赖，优先使用轻量级方案

**实践案例**:
- mq.compensation 模块使用 JdbcTemplate 而非 MyBatis-Plus
- 集成方只需提供 DataSource 即可使用补偿机制
- 表名可通过配置文件自定义

### MQ 可靠发送与补偿机制

**可靠性保障**:
- 使用 JdbcTemplate 实现数据访问（不依赖 MyBatis-Plus）
- 补偿记录保存失败必须抛出异常
- 支持可靠消息发送和失败补偿

### 本地开发优化

#### 禁用消费者加速启动
使用 `@Profile("!dev")` 注解在本地开发环境禁用 RocketMQ 消费者

**优势**:
- 加快本地启动速度
- 减少不必要的资源消耗
- 避免连接远程 MQ 的问题

#### 条件装配
使用 `@ConditionalOnProperty` 控制组件加载

### 高并发场景优化

**在线状态更新策略**:
- 通过 Token 刷新机制间接更新在线状态
- 避免每次请求都写入 Redis
- 降低 Redis 压力

## 常见问题与陷阱

### Spring Boot Starter 自动配置问题

#### 问题 1: 类路径错误
**现象**: AutoConfiguration.imports 文件中引用的类路径与实际包结构不一致

**解决**: 
- 按功能模块组织包结构
- 确保 imports 文件中的类路径完全正确

#### 问题 2: @Value 缺少默认值
**现象**: 启动时找不到配置项报错

**解决**: 
```java
// 错误
@Value("${property}")

// 正确
@Value("${property:default_value}")
```

### RocketMQTemplate 注入失败

**现象**: 构造器注入 RocketMQTemplate 导致启动报错 "Bean 未找到"

**原因**: 构造器注入时 Bean 尚未创建完成

**解决**: 
- 使用字段注入或 setter 注入
- 或使用 @Lazy 注解延迟加载

### 验签性能优化

**原则**: 验签签名计算不包含 body

**原因**: 
- 减少前端计算压力
- 提高请求处理速度
- 基于 Header+Path 的轻量级验签已足够安全
