## DDD 架构规范

### 分层架构

#### 依赖方向
```
interfaces → application → domain ← infrastructure
```

**原则**: 
- 严格遵循依赖方向，禁止反向依赖
- 领域层不依赖任何框架和基础设施
- 通过 Repository 接口与基础设施层解耦

#### 各层职责

##### 1. Interfaces 层（用户接口层）
**职责**:
- 接收 HTTP 请求
- 参数校验（@Valid）
- 响应格式化
- 权限验证
- 日志记录（通过 AOP）

**禁止**:
- ❌ 包含业务逻辑
- ❌ 直接操作数据库
- ❌ 调用其他微服务（应通过 SDK/Feign）

**示例**:
```java
@RestController
@RequestMapping("/api/users")
public class UserController {
    
    @Autowired
    private UserService userService;
    
    @PostMapping
    public Result<UserVO> createUser(@Valid @RequestBody CreateUserRequest request) {
        // 只做参数校验和响应格式化
        UserVO user = userService.createUser(request);
        return Result.success(user);
    }
}
```

##### 2. Application 层（应用层）
**职责**:
- 协调领域对象完成业务用例
- 事务控制
- DTO 转换

**禁止**:
- ❌ 包含核心业务规则
- ❌ 直接操作数据库

**示例**:
```java
@Service
@Transactional
public class UserApplicationService {
    
    @Autowired
    private UserRepository userRepository;
    
    @Autowired
    private UserAssembler assembler;
    
    public UserVO createUser(CreateUserRequest request) {
        // 协调领域对象
        UserAggregate user = UserFactory.create(request);
        userRepository.save(user);
        return assembler.toVO(user);
    }
}
```

##### 3. Domain 层（领域层）- 核心
**职责**:
- 聚合根（Aggregate Root）
- 实体（Entity）
- 值对象（Value Object）
- 领域服务（Domain Service）
- 仓储接口（Repository Interface）
- **核心业务规则**
- 领域事件（Domain Event）

**禁止**:
- ❌ 依赖任何框架
- ❌ 依赖基础设施
- ❌ 包含技术实现细节
- ❌ 依赖 Spring 注解

**示例**:
```java
// 聚合根
public class UserAggregate {
    private UserId id;
    private String username;
    private Email email;
    
    // 业务方法
    public void changeEmail(Email newEmail) {
        // 业务规则验证
        if (this.email.equals(newEmail)) {
            throw new DomainException("新邮箱不能与原邮箱相同");
        }
        this.email = newEmail;
        // 发布领域事件
        registerEvent(new EmailChangedEvent(this.id, newEmail));
    }
}

// 值对象
public class Email {
    private final String value;
    
    public Email(String value) {
        if (!isValid(value)) {
            throw new DomainException("无效的邮箱地址");
        }
        this.value = value;
    }
}

// 仓储接口
public interface UserRepository {
    UserAggregate findById(UserId id);
    void save(UserAggregate user);
}
```

##### 4. Infrastructure 层（基础设施层）
**职责**:
- 实现 Repository 接口
- 数据库访问（MyBatis Plus）
- 缓存操作（Redis）
- 消息队列操作
- 第三方服务调用

**示例**:
```java
@Repository
public class UserRepositoryImpl implements UserRepository {
    
    @Autowired
    private UserMapper userMapper;
    
    @Override
    public UserAggregate findById(UserId id) {
        UserDO userDO = userMapper.selectById(id.getValue());
        return UserConverter.toAggregate(userDO);
    }
    
    @Override
    public void save(UserAggregate user) {
        UserDO userDO = UserConverter.toDO(user);
        userMapper.insertOrUpdate(userDO);
    }
}
```

## 命名规范

### DDD 对象命名

#### 基础设施层
**数据库表映射对象**: `XXXDO`

```java
// ✅ 正确
public class UserDO { }
public class OrderDO { }
public class ProductDO { }

// ❌ 错误 - 避免与领域层实体混淆
public class UserEntity { }
```

#### 领域层
**聚合根**: `XXXAggregate`

```java
// ✅ 正确
public class UserAggregate { }
public class OrderAggregate { }
public class ProductAggregate { }
```

**领域实体**: 直接使用领域名词

```java
// ✅ 正确
public class OrderItem { }
public class Address { }
public class ShoppingCart { }
```

**值对象**: 体现不可变性

```java
// ✅ 正确
public class Money { }
public class Email { }
public class PhoneNumber { }
```

#### 应用层
**DTO**: `XXXRequest` / `XXXResponse` / `XXXDTO`

```java
// 请求对象
public class CreateUserRequest { }
public class UpdateOrderRequest { }

// 响应对象
public class UserVO { }
public class OrderVO { }

// 数据传输对象
public class UserDTO { }
```

#### 接口层
**Controller**: `XXXController`

```java
@RestController
public class UserController { }
```

### 其他命名规范

#### Repository 接口
```java
public interface UserRepository { }
public interface OrderRepository { }
```

#### Repository 实现
```java
@Repository
public class UserRepositoryImpl implements UserRepository { }
```

#### Mapper（MyBatis Plus）
```java
@Mapper
public interface UserMapper extends BaseMapper<UserDO> { }
```

#### Service（应用服务）
```java
@Service
public class UserApplicationService { }
```

#### Factory（工厂类）
```java
// Framework 模块中的工厂类
public class WarnChannelFactory { }
public class NotificationFactory { }
```

#### Assembler/Converter（对象转换器）
```java
@Component
public class UserAssembler { }

public class UserConverter { }
```

## 模块职责划分

### Framework vs Starter

#### Framework 模块
**职责**:
- 提供核心功能实现
- 工厂类（如 WarnChannelFactory）
- 工具类和通用组件
- 可被多个 Starter 引用

**示例结构**:
```
youyu-framework/
├── warn/
│   ├── channel/
│   │   └── WarnChannelFactory.java  // 工厂类在这里
│   └── service/
├── cache/
├── anti-shake/
└── mq/
    └── compensation/  // 使用 JdbcTemplate
```

#### Starter 模块
**职责**:
- 自动配置（AutoConfiguration）
- Bean 创建和管理
- 条件装配（@ConditionalOnProperty）
- 对外提供开箱即用的能力

**示例结构**:
```
youyu-starter/
├── src/main/resources/
│   └── META-INF/
│       └── spring/
│           └── org.springframework.boot.autoconfigure.AutoConfiguration.imports
└── src/main/java/
    └── com.youyu.starter.autoconfigure/
        ├── web/
        ├── security/
        ├── data/
        └── logging/
```

**原则**: 
- 工厂类放在 framework
- 自动配置放在 starter
- starter 依赖 framework

### API / Impl / SDK / Bootstrap

#### API 模块
**职责**:
- 接口定义
- DTO 定义
- Feign Client 定义

**示例**:
```java
// Feign Client
@FeignClient(name = "user-service")
public interface UserFeignClient {
    @GetMapping("/api/users/{id}")
    Result<UserVO> getUserById(@PathVariable Long id);
}
```

#### Impl 模块
**职责**:
- 接口实现
- 业务逻辑
- DDD 四层架构实现

#### SDK 模块
**职责**:
- 封装 API 调用
- 提供便捷的客户端
- 隐藏底层实现细节

**示例**:
```java
@Component
public class UserSdkClient {
    
    @Autowired
    private UserFeignClient userFeignClient;
    
    public UserVO getUser(Long id) {
        Result<UserVO> result = userFeignClient.getUserById(id);
        return result.getData();
    }
}
```

#### Bootstrap 模块
**职责**:
- 启动类
- 配置文件
- 依赖组装

## 异常处理规范

### 异常分类

#### 1. 领域异常（DomainException）
**用途**: 业务规则违反

```java
public class DomainException extends RuntimeException {
    public DomainException(String message) {
        super(message);
    }
}

// 使用
if (balance.compareTo(amount) < 0) {
    throw new DomainException("余额不足");
}
```

#### 2. 应用异常（ApplicationException）
**用途**: 应用层错误

```java
public class ApplicationException extends RuntimeException {
    public ApplicationException(String message) {
        super(message);
    }
}
```

#### 3. 基础设施异常（InfrastructureException）
**用途**: 技术层面错误

```java
public class InfrastructureException extends RuntimeException {
    public InfrastructureException(String message, Throwable cause) {
        super(message, cause);
    }
}
```

### 全局异常处理

```java
@RestControllerAdvice
public class GlobalExceptionHandler {
    
    @ExceptionHandler(DomainException.class)
    public Result<Void> handleDomainException(DomainException e) {
        log.warn("业务异常: {}", e.getMessage());
        return Result.fail(BizCode.BIZ_ERROR, e.getMessage());
    }
    
    @ExceptionHandler(ApplicationException.class)
    public Result<Void> handleApplicationException(ApplicationException e) {
        log.error("应用异常", e);
        return Result.fail(BizCode.APP_ERROR, e.getMessage());
    }
    
    @ExceptionHandler(Exception.class)
    public Result<Void> handleException(Exception e) {
        log.error("系统异常", e);
        return Result.fail(BizCode.SYSTEM_ERROR, "系统繁忙，请稍后重试");
    }
}
```

### 补偿记录保存失败必须抛出异常

**原则**: 补偿表保存失败时必须抛出异常，让业务层感知

**原因**:
- 确保数据一致性
- 避免静默失败导致补偿机制失效
- 让上层业务能够正确处理异常情况

**示例**:
```java
public void saveCompensationRecord(CompensationRecord record) {
    int rows = jdbcTemplate.update(SQL, params);
    if (rows == 0) {
        // ❌ 错误 - 不要吞掉异常
        // log.error("保存补偿记录失败");
        
        // ✅ 正确 - 抛出异常
        throw new InfrastructureException("保存补偿记录失败");
    }
}
```

## 安全规范

### 验签规范

#### 轻量级验签（网关层）
**签名计算范围**: Header + Path（**不包含 Body**）

**原因**:
- 减少前端计算压力
- 提高请求处理速度
- 基于 Header+Path 的验签已足够安全

**示例**:
```java
// 签名生成
String sign = MD5(appKey + path + timestamp + nonce + secret);

// 签名验证
String expectedSign = MD5(appKey + path + timestamp + nonce + secret);
if (!sign.equals(expectedSign)) {
    throw new SecurityException("签名验证失败");
}
```

#### 分层安全架构
- **外部网关**: 负责通用安全（轻量级验签）
- **业务微服务**: 负责核心业务安全（如需可对 Body 全量验签）

### JWT Token 规范

#### Refresh Token 滚动刷新
**方案**: 轻量级零存储

**实现**:
- 不单独存储 Refresh Token
- 利用 JWT 自然过期机制
- 滚动刷新延长会话有效期

```java
public TokenPair refreshToken(String oldRefreshToken) {
    // 验证旧 Refresh Token
    Claims claims = jwtUtil.parseToken(oldRefreshToken);
    
    // 生成新的 Token 对
    String newAccessToken = jwtUtil.generateAccessToken(claims);
    String newRefreshToken = jwtUtil.generateRefreshToken(claims);
    
    return new TokenPair(newAccessToken, newRefreshToken);
}
```

### 设备标识规范

#### 禁止使用 IP 地址
**原因**:
1. 动态 IP：移动网络、DHCP 环境下 IP 频繁变化
2. 代理/VPN：用户使用代理或 VPN 会导致 IP 变化
3. 网络切换：WiFi 与 4G 切换时 IP 也会改变

#### 正确的设备标识
仅使用浏览器/设备本身的固有特征：

```java
// ✅ 正确
String deviceUniqueId = HashUtil.md5(
    userAgent + 
    secChUa + 
    secChUaPlatform + 
    secChUaMobile
);

// ❌ 错误
String deviceUniqueId = HashUtil.md5(ipAddress + userAgent);
```

## 配置规范

### 环境配置分离

#### 配置文件结构
```
src/main/resources/
├── application.yml          # 主配置
├── application-dev.yml      # 开发环境
├── application-uat.yml      # UAT 环境
└── application-prod.yml     # 生产环境
```

### 本地开发优化

#### 禁用消费者加速启动
```yaml
# application-dev.yml
rocketmq:
  consumer:
    enabled: false  # 本地开发禁用消费者
```

或使用注解：
```java
@Profile("!dev")
@Component
public class MessageConsumer {
    // 仅在非 dev 环境加载
}
```

### @Value 必须设置默认值

```java
// ❌ 错误 - 缺少默认值，启动可能失败
@Value("${config.property}")
private String property;

// ✅ 正确 - 设置默认值
@Value("${config.property:default_value}")
private String property;
```

### 条件装配

```java
@Configuration
@ConditionalOnProperty(name = "feature.enabled", havingValue = "true")
public class FeatureAutoConfiguration {
    
    @Bean
    public FeatureService featureService() {
        return new FeatureService();
    }
}
```

## 代码质量检查清单

### Commit 前自查

- [ ] 遵循 DDD 分层架构
- [ ] 命名符合规范（DO/Aggregate/VO 等）
- [ ] 异常处理完善
- [ ] 添加了必要的注释
- [ ] 没有硬编码的配置值

- [ ] 事务注解位置正确

- [ ] 领域层是否纯净（无框架依赖）
